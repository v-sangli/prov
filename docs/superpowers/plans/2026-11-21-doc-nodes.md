# Doc Nodes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Docs get `doc_` IDs and join lineage through `cites` links; lineage walks one `edges` view.

**Architecture:** New `prov.docs` package (layer 3) with DocRecord/DocVersion and `register`; catalog bundles contribute `nodes`/`edges` SQL; lineage becomes a generic walk; prov-journal assigns IDs and registers journal docs.

**Tech Stack:** Python 3.12, pydantic, DuckDB, git CLI, pytest, ruff 0.8.4.

## Global Constraints

- Code stance: lean, fail-loud; no guards/fallbacks/`hasattr`/`getattr(..., default)`; typed closed records.
- Existing tests are the oracle; a red existing test gets a verdict before any fix.
- Registry writes hold `RegistryLock`; never call `catalog.connect` while holding it (it may rebuild, which locks).
- Commands: `.venv/bin/python -m pytest -q`; `uvx ruff@0.8.4 check packages conftest.py`.

### Task 1: generic lineage over `nodes` and `edges` (oracle first)
- Run the lineage tests and save their outputs. Add `nodes: str` and `edges: str` (SQL SELECTs, may be empty) to `CatalogTables`; each existing bundle (runs, artifacts, episodes, datasets) contributes the nodes and edges that `lineage/graph.py` encodes today (`produced`, `input`, `parent`, `member`; labels exactly as `_describe` prints them). The catalog creates views `nodes` and `edges` as unions. Rewrite `lineage/graph.py` to walk `edges` and label from `nodes`.
- Verify: all existing tests pass with none edited; `trace`/`uses` output identical.

### Task 2: `prov.docs` (test first)
- Tests: register assigns and writes `id:` (adding frontmatter when the file has none); cites collect IDs and aliases from frontmatter and body, aliases resolved, own ID excluded; an unknown cite raises DocError; a loose file raises DocError naming the journal rule; a second register with no change appends nothing; an edit appends a version with `dirty=True`; after commit, `commit` is set and `dirty=False`; `remote` is the origin URL or None.
- Implement ids/layout/errors additions, `docs/schema.py`, `docs/register.py` (git via subprocess: `rev-parse --show-toplevel`, `remote get-url origin`, `log -1 --format=%H -- <path>`, `status --porcelain -- <path>`), `docs/tables.py` (docs, doc_cites, nodes, edges), wiring, `prov doc register PATH...`, `prov show doc_…`.
- Tests: `prov trace doc_…` reaches a cited checkpoint and its run; `prov uses <ckpt>` lists the doc.

### Task 3: prov-journal and prov-skills
- `templates/doc.md` gets `id: {id}`; `new_doc` fills a fresh `doc_` ID; the frontmatter lint rule accepts `id`. `prov-journal register` registers every dated journal doc and prints each ID. Tests for both.
- prov-skills `journal/SKILL.md`: a loose note is folded into the journal (as a new dated doc) before registering; run `prov-journal register` at the end of a session.

### Task 4: records and docs
- ADR 0019 "Docs are lineage nodes; lineage walks one edges view" (Accepted at finalize), ADR index; README (package map: `prov.docs`; axes note); usage.md (doc commands, catalog tables `docs`, `doc_cites`, views `nodes`, `edges`); versions per the spec.
